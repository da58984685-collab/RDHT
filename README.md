## DB 전송량(egress) 최적화 메모

- 목록·상태 조회는 필요한 컬럼만 가져옵니다. 사진(base64)·성격·특성 같은 긴 값은 평소 조회에서 제외됩니다.
- 사진은 `/api/img?k=...&v=...` 주소로 제공되며 브라우저/CDN에 1년간 캐시됩니다. 사진을 바꾸면 `v` 값(users.img_ver)이 바뀌어 새 주소가 됩니다. 서명 키는 `IMG_SECRET`(없으면 관리자 비밀번호 기반)입니다.
- 조회(GET) 응답에는 ETag 가 붙어, 내용이 그대로면 본문 없이 304 로 답합니다(브라우저가 자동 처리). 관리자 창 응답은 제외입니다.
- 화면이 숨겨진 탭에서는 상태/알림/메신저/지도 확인을 멈추고, 탭으로 돌아오면 한 번 바로 확인합니다.
- `DATABASE_URL` 은 Neon의 **Pooled connection**(호스트에 `-pooler` 포함) 주소를 쓰세요. 아니면 서버 로그에 경고가 찍힙니다.
- 되돌리려면 이전 버전의 `api/_app.js`, `api/_db.js`, `index.html` 으로 교체하세요. (추가된 `users.img_ver` 열은 남아 있어도 무해합니다.)

## 오염 경계 시스템

- 오염도 30% / 60% / 80% 가 되면 1·2·3단계가 됩니다. 단계가 오르면 화면 위에 경고가 뜨고, 지도가 점점 붉어집니다.
- 1단계 이상: 상점 가격 +10% / +20% / +30% (구매 시에만, 상점 화면에 안내 표시)
- 2단계 이상: 사냥에서 패배하면 골드를 평균 토벌 골드의 10배만큼 잃습니다 (가진 골드가 한도).
- 3단계(80%+): 위험 지역(B·A급) 출입 불가. ("오염도가 높아 해당 지역에 출입할 수 없습니다.")
- 오염 사냥꾼: 2단계 6% · 3단계 12% 확률로 30분마다 등장. 공격력(헌터 최대 체력의 약 15%)·체력(헌터 공격력의 16배)이 높고 최소 10턴은 이어지도록 맞춰져 있으며, 처치하면 오염도가 8% 줄어듭니다. 잡지 않아도 불이익은 없습니다.
- 오염 사냥꾼 강화(서버 전체): 누가 오염 사냥꾼을 토벌하든 서버 토벌 횟수가 1씩 올라, 다음 사냥꾼은 체력 +5% · 공격력 +5% · 보상(경험치·골드) +8%씩 세지고(최대 20단계), 4단계마다 최소 라운드가 +1 늘어납니다(0단계 10라운드 → 20단계 15라운드). 토벌될 때마다 시스템 팝업(제목 "오염 사냥꾼이 토벌되었습니다." · 내용 "오염 사냥꾼이 강화됩니다.")이 모든 헌터에게 자동 전송됩니다. 관리자 창 "오염 사냥꾼 현황"에서 토벌 횟수·마지막 토벌 시각을 보고 자동 팝업을 켜고 끌 수 있습니다(기본 켜짐). 기록은 기존 `settings` 표에 저장되어 새 표는 없습니다.
- 혈월의 잔영: 오염 80~99% 에서만, 30분마다 2% 확률로 등장하는 희귀 몬스터. 보상이 크지만 처치 시 오염도가 올라 100%(폭주)가 될 수 있습니다.
- 두 몬스터 모두 적월문 밖에서만 나옵니다. 수치는 `api/_game.js` 상단(TAINT_*, HUNTER_CHANCE, RARE_CHANCE, SPECIAL_MON)에서 조절합니다.

## 백귀야행 잡귀 출현 수정
- 등급: 예전에는 헌터 등급보다 1~2단계 낮은 등급(사실상 C~D)만 나왔습니다. 이제 잡귀마다 F ~ (헌터 등급+1, 최대 A) 사이에서 고르게 정해집니다. S급은 나오지 않습니다.
- 지역: 예전에는 헌터가 있는 한 지역에만 나왔습니다. 이제 잡귀마다 전국 출현 지역 중 무작위로 흩어집니다. 오염 80% 이상(출입 제한) 헌터에게는 B·A급 위험 지역에 나오지 않습니다.
- 수정 파일: api/_event.js (tick 함수)

## 토벌 실패 확률 상향
- 기본 성공 확률을 낮췄습니다 (쉬움 85→80%, 보통 65→55%, 어려움 40→25%, 매우 어려움 25→15%). 레벨·근력 보정은 그대로입니다.
- 수정 파일: api/_game.js (HUNT_BASE)

## 백귀야행 F·E급 비중 상향
- 잡귀 등급 가중치를 F:E:D:C:B:A = 4:4:1:1:1:1 로 바꿨습니다. 높은 등급 헌터는 F·E급이 약 2/3, 나머지 등급이 약 1/3입니다. (등급 상한은 그대로: 헌터 등급+1, 최대 A급)
- 수정 파일: api/_event.js

## 백귀야행 잡귀 등급별 출몰 주기
- 잡귀도 평소 몬스터처럼 등급 묶음마다 따로 나옵니다: F 1분 · E/D 5분 · C/B 30분 · A 60~120분 (헌터마다 따로 계산). 한 번에 한 마리, 헌터 등급+1(최대 A)까지만 나옵니다.

## 수정: 구매·사용 직후 인벤토리/스탯이 갱신되지 않던 문제
- 원인: 화면은 10초마다 `/api/state` 로 상태를 확인하는데, 확인이 진행 중일 때 구매·아이템 사용 직후의 "다시 확인" 요청이 버려졌습니다. 그러면 구매 전(옛) 응답이 화면에 적용되어 수량이 옛 값으로 보이거나 품목이 없는 것처럼 보였고, 힘의 영약 사용 후 스탯도 옛 값으로 보였습니다.

## 수정: 토벌 중 한 대 치면 전투가 처음으로 돌아가던 문제
- 추정 원인: 토벌 버튼을 누르면 서버에는 전투가 바로 만들어지는데, 화면은 토벌 연출(2~4초) 뒤에야 전투창을 엽니다. 그 사이 10초 주기 상태 확인이 먼저 전투창을 열면, 사용자가 한 대 친 뒤에 늦게 도착한 토벌 응답(1라운드, 체력 가득)이 전투창을 다시 열면서 화면을 처음 상태로 덮어썼습니다.
- 수정(`index.html` 의 `btlOpen`): 이미 열려 있는 같은 전투에 라운드가 같거나 더 낮은 정보가 오면 무시합니다. 서버 전투 로직은 그대로입니다(서버는 라운드가 정상적으로 진행됨을 확인).

- 육성 창의 정사각형 칸에 크기 비교 그림을 넣었습니다. 사람(170cm, 검은 픽셀아트)과 선택한 몬스터(검은 픽셀아트)가 같은 눈금 위에 서 있고, 몬스터 크기는 `FRIENDLY_MON` 의 `cm` 에 맞춰 달라집니다. 가로 눈금선은 10cm마다 있고 50cm 선은 굵게, 1m 단위는 `1M`·`2M` 로 표시합니다. 몬스터가 190cm 를 넘으면 눈금 범위가 3M·4M·5M 로 넓어지고 사람은 그만큼 작게 보입니다. 칸 배경은 검은 그림이 보이도록 밝은 색입니다. 그림은 `index.html` 안의 `RAI_H`(사람)·`RAI_M`(몬스터) 에 들어 있습니다.
- 육성 창에서 이미 선택한 몬스터 버튼을 한 번 더 누르면 자세히 보기로 바뀝니다. 왼쪽에 같은 크기 비교 정사각형, 오른쪽에 `이름`(유저가 지어 주는 이름, 12자까지, 저장 버튼) · `종`(몬스터 이름·등급·크기) · `채집 시기` · `외관`(외관 설명) · `특징` 이 나옵니다. `← 목록` 으로 돌아갑니다.
- 서버: `GET /api/raise` 가 얻은 몬스터에 한해 지어 준 이름·채집 시기·외관·특징을 함께 돌려주고, `POST /api/raise/name` 으로 이름을 저장합니다. `user_mons` 표에 `nick` 칸이 추가되었습니다(`_db.js` 의 ALTER 목록). 채집 시기는 몬스터를 얻은 시각(`got_at`)입니다.
- 육성 창 그림 색을 사이트 색에 맞췄습니다. 쓰는 색은 어두운 검붉은 바탕, 메인(붉은색 `#d4202e`), 포인트(크림색 `#f3e9e7`) 세 가지뿐입니다(`index.html` 의 `RC`). 크기 비교 칸은 어두운 바탕에 사람은 크림색, 몬스터는 붉은색입니다.
- 자세히 보기의 정사각형 칸은 크기 비교 대신 도트 풍경(밤하늘·달·산·소나무·땅) 위에 몬스터만 서 있는 그림으로 바꿨습니다. 몬스터는 통통 뛰어오르고(그림자도 함께 변함) 약 3초마다 눈을 깜빡입니다. 1초에 약 8번만 다시 그리고, 자세히 보기를 닫거나 다른 탭을 보면 멈춥니다. 기기의 '동작 줄이기' 설정이 켜져 있으면 가만히 있습니다.
- 우호 몬스터 30종에 고유 효과를 넣었습니다. 몬스터마다 토벌 보너스 1개와 PvP 보너스 1개이고, 등급이 높을수록 수치가 커집니다(E 1배 · D 2배 · C 3배 · B 4배 · A 5배 · S 7배). 효과 이름과 종류는 `_game.js` 의 `FRIEND_FX` 표 한 곳에서 고치고, 단계당 수치는 `FX_HUNT`·`FX_PVP` 에서 고칩니다. 자세히 보기 창의 `토벌 효과`·`PvP 효과` 칸에 보입니다.
- 아직 실제 토벌·PvP 계산에는 적용하지 않았습니다(몬스터를 데리고 다니는 방식과 PvP 규칙이 아직 없기 때문입니다). 보여 주기용 데이터입니다.

## PvP 전용 스탯 (설계 단계 — 아직 화면·전투에는 연결하지 않음)
- PvP 는 토벌과 따로 레벨 없이 체력·근력·민첩·행운·오염도 5가지 스탯만 씁니다. 모두에게 포인트 15를 같게 주고, 스탯마다 최소 1·최대 5입니다(처음엔 모두 1, 10포인트를 나눠 씀). `_game.js` 의 `PVP_*`, `pvpStatsOk`, `pvpDerive` 에 규칙과 계산식이 있습니다.
- 우호 몬스터의 PvP 효과를 이 스탯 체계에 맞춰 다시 썼습니다(`FRIEND_FX` 의 PvP 부분, `FX_PVP`). 레벨 보상(경험치·골드)이 없어졌기 때문에 승리 경험치·골드 효과는 없앴습니다. 몬스터 효과는 스탯 효과 위에 더해집니다.
- PvP 규칙 값을 `_game.js` 의 `PVP`·`PVP_STAT_TEXT` 에 정리했습니다(레벨 없이 체력·근력·민첩·행운·오염도 각 1~5, 총 15포인트, PvP 체력 100, 최소 10턴). 근력=공격 피해, 민첩=회피·선공, 행운=치명타, 체력=받는 피해 감소, 오염도=침식 피해(대신 반동). 값은 모의 전투로 맞췄습니다(어느 배분이 압도하지 않도록, 평균 약 14.5턴). 아직 PvP 전투 화면·대전 기능은 없습니다(값만 준비).
- 우호 몬스터의 PvP 효과를 위 규칙에 맞게 다시 썼습니다(`FX_PVP` 표: 공격 피해·회피·치명타 확률·치명타 피해·받는 피해 감소·침식·피해 반사). 종류마다 같은 등급이면 비슷한 가치가 되도록 모의 전투로 맞췄습니다.
- 육성 자세히 보기에 `산책 · 먹이 · 목욕 · 방생` 버튼과 상태(포만감·청결·친밀도)를 넣었습니다. 동행(데리고 다니기)은 한 마리뿐입니다: 산책 = 동행 시작(다른 몬스터가 동행 중이면 그 몬스터는 자동으로 산책을 마칩니다), 산책 마치기 = 동행 해제.
- 규칙(`_app.js` 의 `RAISE`): 포만감은 1시간에 4, 청결은 1시간에 2씩 줄어듭니다. 먹이 +30(30분에 한 번), 목욕 +40(1시간에 한 번), 둘 다 친밀도 +1. 산책을 마칠 때 10분마다 친밀도 +1(한 번에 최대 +6). 포만감이 0이면 산책을 나갈 수 없습니다. 방생은 한 번 더 눌러야 실행되고 되돌릴 수 없습니다. 친밀도 최대 100.
- 서버: `POST /api/raise/act` (`act` = walk · feed · bath · release). `user_mons` 표에 `full`·`full_at`·`clean`·`clean_at`·`bond`·`walk_at`·`fed_last`·`bath_last` 칸이 추가되었습니다. 동행 몬스터의 토벌·PvP 효과를 실제 전투에 적용하는 것은 아직 하지 않았습니다.
- 친밀도가 더 빨리 오르도록 바꿨습니다: 먹이 +3, 목욕 +3, 산책은 10분마다 +1(한 번에 최대 +10, 100분). 대략 하루 12시간 접속하며 6시간에 한 번 돌봐 주면 약 3일에 100, 2~3시간마다 돌봐 주면 1.5일 안팎입니다. 수치는 `_app.js` 의 `RAISE` 에서 고칩니다.
- 기기에 `전장` 앱을 만들었습니다. 누르면 팝업이 열리고 가운데에 `매칭` 버튼, 그 아래에 현재 PvP 스탯(체력·근력·민첩·행운·오염도)과 동행 몬스터가 작게 표시됩니다. 매칭 버튼은 아직 "열리지 않았어요" 안내만 보여 줍니다. PvP 스탯은 기본 3·3·3·3·3(합계 15)이고 `users.pvp_stats` 에 저장하며, 스탯을 직접 나누는 화면은 아직 없습니다. 서버: `GET /api/pvp/me`.

## 친밀도 개편 · 먹이 조합 (육성)
- 친밀도 상승을 크게 늦췄습니다. 먹이 +2, 목욕 +1, 산책 20분당 +1(한 번에 최대 +4), 몬스터당 하루 최대 +20(한국시간 자정 기준 초기화). 최대 100까지 최소 5일이 걸립니다.
- 친밀도 30 단위로 효과 강화: 0~29 ×1 / 30~59 ×1.3 / 60~89 ×1.6 / 90~100 ×2 (토벌·PvP 효과 모두, 상세 화면에 단계 표시).
- 먹이 조합: 일반 등급 조합 재료 30개(직접 선택, +1/+5/+10 버튼)로 먹이 1개. 먹이를 줄 때 먹이 1개를 소모하며, 없으면 줄 수 없습니다. (`POST /api/raise/craft`)
- DB: `users.mon_food`, `user_mons.bond_day`, `user_mons.bond_today` 컬럼이 자동 추가됩니다.

## PVP 개편 (스탯 창 · 매칭 · 턴제 전투 · 랭킹 · 동행)
- **테스트 계정 삭제**: 코드 `AAAA-AA11` 로그인과 자동 생성 기능을 없앴습니다. 이미 DB에 만들어져 있으면 첫 요청 때 한 번 지웁니다(환경 변수 `TEST_ACCOUNT`, `TEST_ACCOUNT_PW` 는 더 이상 쓰지 않습니다).
- **PVP 스탯 창**: 스탯 카드의 `PVP 스탯 (오각형)` 버튼. 체력·근력·민첩·행운·오염도 각 1~5, 합계 15를 오각형 그래프로 보며 `+`/`−` 로 나누고 저장합니다. 매칭 대기 중에는 바꿀 수 없습니다. (`POST /api/pvp/stats`)
- **장비는 토벌 전용**: PVP 전투 계산은 PVP 스탯과 동행 몬스터 효과만 사용하며, 장비·등급·레벨(전투력)은 전혀 쓰지 않습니다.
- **전투 수치(0~100)**: 같은 스탯·몬스터로 기준 상대(모든 스탯 3, 몬스터 없음)와 600번 싸워 얻은 승률입니다. 기준 상대는 50입니다.
- **매칭**: 전장의 `매칭` 버튼으로 대기열에 들어가고, 전투 수치 차이가 5 이내인 상대와 연결됩니다. 20초 넘게 기다리면 7 이내까지 넓어집니다(그 이상은 연결하지 않음). 2초마다 확인하며, 창을 닫으면 대기가 취소됩니다.
- **전투**: 턴제. 민첩이 높은 쪽이 먼저 공격하고 상대가 반격하며, 턴 끝에 침식·반동이 들어갑니다. 최소 10턴은 체력이 1 밑으로 내려가지 않고, 한쪽 체력이 0이 되면 자동 종료, 40턴이 지나면 남은 체력이 많은 쪽이 승리합니다. 결과는 두 사람 모두에게 한 턴씩 재생됩니다(건너뛰기 가능).
- **패배 회복**: 패배하면 PvP 체력이 0이 되어 10분에 걸쳐 100으로 돌아오며, 그동안은 매칭할 수 없습니다.
- **유저 랭킹**: 전장 첫 화면의 `유저 랭킹` 버튼. 승리 수 → 승률 → 적은 패배 순으로 상위 100명과 내 순위를 보여 줍니다.
- **동행**: 몬스터 더보기의 `산책` 이 `동행` / `동행 해제` 로 바뀌었습니다. 동행 중인 한 마리가 PVP 파트너가 되어 그 몬스터의 PvP 효과(친밀도 단계 반영)가 전투에 적용됩니다. 포만감이 0이면 동행을 시작할 수 없고, 동행 중 0이 되면 효과가 붙지 않습니다.
- DB: `pvp_queue`, `pvp_battles` 테이블과 `users.pvp_win`, `pvp_lose`, `pvp_lock` 컬럼이 자동으로 추가됩니다.

## PVP 회복 포션 (상점)
- 상점에 `PVP 회복 포션` 추가: 가격 2000 G, PVP 체력을 **전체 회복**(100)합니다. 오염 단계에 따른 상점 가격 인상은 적용하지 않아 항상 2000 G 입니다.
- 인벤토리에서 `사용`하면 패배 후 회복 대기(10분)가 즉시 풀립니다. PVP 체력이 이미 가득 차 있으면 사용되지 않고 포션도 줄지 않습니다.
- 서버를 처음 쓸 때 한 번만 자동 등록되며, 관리자 화면에서 가격·설명을 고치거나 삭제할 수 있습니다(삭제해도 다시 만들지 않음). 관리자 상품 효과 목록에 `PVP 체력 전체 회복` 이 추가되었습니다.
