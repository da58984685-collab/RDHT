## DB 전송량(egress) 최적화 메모

- 목록·상태 조회는 필요한 컬럼만 가져옵니다. 사진(base64)·성격·특성 같은 긴 값은 평소 조회에서 제외됩니다.
- 사진은 `/api/img?k=...&v=...` 주소로 제공되며 브라우저/CDN에 1년간 캐시됩니다. 사진을 바꾸면 `v` 값(users.img_ver)이 바뀌어 새 주소가 됩니다. 서명 키는 `IMG_SECRET`(없으면 관리자 비밀번호 기반)입니다.
- 조회(GET) 응답에는 ETag 가 붙어, 내용이 그대로면 본문 없이 304 로 답합니다(브라우저가 자동 처리). 관리자 창 응답은 제외입니다.
- 화면이 숨겨진 탭에서는 상태/알림/메신저/지도 확인을 멈추고, 탭으로 돌아오면 한 번 바로 확인합니다.
- `DATABASE_URL` 은 Neon의 **Pooled connection**(호스트에 `-pooler` 포함) 주소를 쓰세요. 아니면 서버 로그에 경고가 찍힙니다.
- 되돌리려면 이전 버전의 `api/_app.js`, `api/_db.js`, `index.html` 으로 교체하세요. (추가된 `users.img_ver` 열은 남아 있어도 무해합니다.)

## 오염 경계 시스템

- 오염도 30% / 60% / 80% 가 되면 1·2·3단계가 됩니다. 단계가 오르면 화면 위에 경고가 뜨고, 지도가 점점 붉어집니다.
- 1단계 이상: 상점 가격 +10% / +20% / +30% (구매 시에만, 상점 화면에 안내 표시)
- 2단계 이상: 사냥에서 패배하면 골드를 평균 토벌 골드의 10배만큼 잃습니다 (가진 골드가 한도).
- 3단계(80%+): 위험 지역(B·A급) 출입 불가. ("오염도가 높아 해당 지역에 출입할 수 없습니다.")
- 오염 사냥꾼: 2단계 6% · 3단계 12% 확률로 30분마다 등장. 공격력(헌터 최대 체력의 약 15%)·체력(헌터 공격력의 16배)이 높고 최소 10턴은 이어지도록 맞춰져 있으며, 처치하면 오염도가 8% 줄어듭니다. 잡지 않아도 불이익은 없습니다.
- 오염 사냥꾼 강화(서버 전체): 누가 오염 사냥꾼을 토벌하든 서버 토벌 횟수가 1씩 올라, 다음 사냥꾼은 체력 +5% · 공격력 +5% · 보상(경험치·골드) +8%씩 세지고(최대 20단계), 4단계마다 최소 라운드가 +1 늘어납니다(0단계 10라운드 → 20단계 15라운드). 토벌될 때마다 시스템 팝업(제목 "오염 사냥꾼이 토벌되었습니다." · 내용 "오염 사냥꾼이 강화됩니다.")이 모든 헌터에게 자동 전송됩니다. 관리자 창 "오염 사냥꾼 현황"에서 토벌 횟수·마지막 토벌 시각을 보고 자동 팝업을 켜고 끌 수 있습니다(기본 켜짐). 기록은 기존 `settings` 표에 저장되어 새 표는 없습니다.
- 혈월의 잔영: 오염 80~99% 에서만, 30분마다 2% 확률로 등장하는 희귀 몬스터. 보상이 크지만 처치 시 오염도가 올라 100%(폭주)가 될 수 있습니다.
- 두 몬스터 모두 적월문 밖에서만 나옵니다. 수치는 `api/_game.js` 상단(TAINT_*, HUNTER_CHANCE, RARE_CHANCE, SPECIAL_MON)에서 조절합니다.

## 백귀야행 잡귀 출현 수정
- 등급: 예전에는 헌터 등급보다 1~2단계 낮은 등급(사실상 C~D)만 나왔습니다. 이제 잡귀마다 F ~ (헌터 등급+1, 최대 A) 사이에서 고르게 정해집니다. S급은 나오지 않습니다.
- 지역: 예전에는 헌터가 있는 한 지역에만 나왔습니다. 이제 잡귀마다 전국 출현 지역 중 무작위로 흩어집니다. 오염 80% 이상(출입 제한) 헌터에게는 B·A급 위험 지역에 나오지 않습니다.
- 수정 파일: api/_event.js (tick 함수)

## 토벌 실패 확률 상향
- 기본 성공 확률을 낮췄습니다 (쉬움 85→80%, 보통 65→55%, 어려움 40→25%, 매우 어려움 25→15%). 레벨·근력 보정은 그대로입니다.
- 수정 파일: api/_game.js (HUNT_BASE)

## 백귀야행 F·E급 비중 상향
- 잡귀 등급 가중치를 F:E:D:C:B:A = 4:4:1:1:1:1 로 바꿨습니다. 높은 등급 헌터는 F·E급이 약 2/3, 나머지 등급이 약 1/3입니다. (등급 상한은 그대로: 헌터 등급+1, 최대 A급)
- 수정 파일: api/_event.js

## 백귀야행 잡귀 등급별 출몰 주기
- 잡귀도 평소 몬스터처럼 등급 묶음마다 따로 나옵니다: F 1분 · E/D 5분 · C/B 30분 · A 60~120분 (헌터마다 따로 계산). 한 번에 한 마리, 헌터 등급+1(최대 A)까지만 나옵니다.
- 잡귀 F급도 평소처럼 5분 안에 못 잡으면 사라집니다. 동시에 떠 있는 잡귀 상한은 20마리입니다.
- 이전의 "6~12분마다 2~3마리" 방식과 F·E 가중치(4:4:1:1:1:1)는 이 방식으로 대체되었습니다.

## 게이트웨이브 알림 벨 + @멘션
- 알림 벨(Lucian UX/UI #074, MIT): 게이트웨이브 목록 화면 오른쪽 위. 새 알림이 오면 벨이 흔들리고 배지 숫자가 튀어 오릅니다. 탭은 전체 / 멘션 / 설정. 항목을 누르면 읽음 처리되고 그 글이 열립니다. '모두 읽음', 벨 다시 누르기·Esc로 닫기 지원. 읽음 표시는 기기(브라우저)에 저장됩니다. 사이트가 어두운 테마 하나뿐이라 색 토큰은 사이트 변수에 연결했습니다.
- 알림 설정은 벨 안의 '설정' 탭으로 옮겼습니다(예전 '알림 설정' 별도 화면 삭제). 새 글 / 내 글에 댓글 / 나에게 답글은 그대로이고 '나를 태그했을 때'가 추가됐습니다. 알림음·토스트 동작은 그대로입니다.
- @멘션: 글·댓글에 `@헌터이름`을 쓰면 '친구'인 헌터만 언급으로 저장되고 알림이 갑니다 (친구가 아니면 그냥 글자). 입력 중 @를 치면 친구 목록 자동완성(↑↓, Enter/Tab, Esc). 본문에서는 언급된 이름이 강조됩니다. 한 번에 최대 5명.
- 서버: gw_mentions 표(자동 생성), GET /api/gw/alerts(벨 목록), /api/gw/notify에 mentions 추가. 글·댓글·계정 삭제 시 멘션도 함께 삭제됩니다.
- 수정 파일: index.html, api/_app.js, api/_db.js

## 수정: 구매·사용 직후 인벤토리/스탯이 갱신되지 않던 문제
- 원인: 화면은 10초마다 `/api/state` 로 상태를 확인하는데, 확인이 진행 중일 때 구매·아이템 사용 직후의 "다시 확인" 요청이 버려졌습니다. 그러면 구매 전(옛) 응답이 화면에 적용되어 수량이 옛 값으로 보이거나 품목이 없는 것처럼 보였고, 힘의 영약 사용 후 스탯도 옛 값으로 보였습니다.
- 수정(`index.html` 의 `pollState`): 확인 중에 요청이 들어오면 버리지 않고 현재 응답이 끝나자마자 한 번 더 확인합니다. 서버(조합·사용·구매·수량 합산)는 로컬에서 정상 동작을 확인했습니다.

## 수정: 토벌 중 한 대 치면 전투가 처음으로 돌아가던 문제
- 추정 원인: 토벌 버튼을 누르면 서버에는 전투가 바로 만들어지는데, 화면은 토벌 연출(2~4초) 뒤에야 전투창을 엽니다. 그 사이 10초 주기 상태 확인이 먼저 전투창을 열면, 사용자가 한 대 친 뒤에 늦게 도착한 토벌 응답(1라운드, 체력 가득)이 전투창을 다시 열면서 화면을 처음 상태로 덮어썼습니다.
- 수정(`index.html` 의 `btlOpen`): 이미 열려 있는 같은 전투에 라운드가 같거나 더 낮은 정보가 오면 무시합니다. 서버 전투 로직은 그대로입니다(서버는 라운드가 정상적으로 진행됨을 확인).

  - API: `GET /api/gw?cat=`, `POST /api/gw/post` 의 `cat`, `/api/gw/notify` 의 `postsBy`(카테고리별 새 글 수), `/api/gw/alerts` 의 `cat`.

- 캐릭터 칸에 `내 코드 · XXXX-XXXX` 표시(본인 화면에서만).
- 몬스터 출몰 알림 위치: `국가, 세부위치` (예: `이탈리아, 베네치아 수로`). SS급처럼 국가 단위 출몰은 국가 이름만 표시.

## 특징 수정 · 더보기 · 게이트웨이브 간단 프로필
- 유저창 캐릭터 칸의 `특징 수정` 블록 버튼 → 팝업에 기존 특징이 채워져 있고 수정·저장 (최대 5개, 칸당 50자). `POST /api/me/traits`.
- 메시지란 친구 간단 프로필에 `더보기` 블록 버튼 → 그 친구의 특징 팝업. (`/api/friend/profile` 에 `traits` 추가)
- 게이트웨이브에서 닉네임(글 목록·글 보기·댓글)을 누르면 같은 간단 프로필(더보기 포함)이 팝업으로 뜹니다. `GET /api/gw/profile?post=번호` 또는 `?comment=번호` — 글/댓글 번호로 작성자를 찾으며 헌터 코드는 내려주지 않습니다.
  - 친구가 아닌 헌터에게는 현재 위치를 숨깁니다.
  - '비공개 유저'는 친구가 아닌 사람에게 이름·등급·이미지만 보이고 더보기는 막힙니다.

## 게이트웨이브 닉네임 옆 작은 프로필 사진 (+ 사진 눌러도 간단 프로필)
- DB: `users.thumb` 칸 추가(`_db.js` ALTER). 64×64 JPEG, 보통 2KB 안팎(최대 약 10KB). 큰 원본(`image`, 최대 512KB)과 따로 저장해서 목록이 가볍습니다.
- 사진 주소 `GET /api/thumb?k=…&v=…` 는 이 칸만 읽고, 1년 캐시(브라우저·CDN)입니다. 큰 원본은 읽지 않습니다. `thumb` 은 모든 헌터 조회에서 제외해(`_userCols`) 평소 요청에 딸려 오지 않습니다.
- 만드는 곳은 화면입니다(서버에 이미지 변환 도구가 없음): 가입·사진 변경 때 함께 올리고(`thumb`), 예전에 올린 사진은 그 헌터가 접속하면 이 기기에서 한 번 만들어 `POST /api/me/thumb` 로 보충합니다. 보충 전에는 이니셜 아이콘이 보입니다(큰 원본으로 대체하지 않음).
- 관리자가 사진을 바꾸면 `thumb` 을 비우고, 그 헌터가 접속할 때 다시 만들어집니다. 사진을 삭제하면 같이 비워집니다.
- 목록·글 보기·댓글의 닉네임 옆 사진을 누르면 닉네임과 똑같이 간단 프로필(더보기 포함)이 뜹니다.
